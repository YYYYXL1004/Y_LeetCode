## 5.6
- 0-1 背包 & 完全背包专题：完成 9 道题目（7 LeetCode + 2 洛谷），系统梳理背包问题的两大分支——0-1背包（每个物品只能选一次）与完全背包（每个物品可无限选）
  - 题型模板（可迁移）：0-1 背包变体——问题转化
    - 适用信号：题目不直接给"物品+容量"，需要通过数学转化构造背包模型
    - 常见转化：差值最小化 → 分成两堆使一堆尽量接近 sum/2（1049）；加减号分配 → 正数子集和为 (sum+target)/2（494）；多维约束 → 二维费用背包（474）
    - 坑点：转化后需检查可行性——(sum+target) 必须为偶数且 |target| <= sum（494）；二维费用需对两个容量维度都倒序遍历（474）
  - 题型模板（可迁移）：完全背包变体——排列 vs 组合
    - 关键区别：求**组合数**时外层遍历物品、内层正序遍历容量（518）；求**排列数**时外层遍历容量、内层遍历物品（377、70++）
    - 适用信号：求"凑出目标的方案数"时，先判断是组合还是排列，决定循环顺序
    - 坑点：279（完全平方数）因为不是求排列，两个循环顺序可颠倒；377 必须先遍历背包再遍历物品才能得到排列数
  - 1049：最后一块石头的重量 II，0-1背包（转化：分成两堆使差最小）
    - 核心思路：问题转化为找一堆和尽量接近 sum/2，用0-1背包求最大装载量
    - 坑点：返回值是 (sum - dp[target]) - dp[target]，即两堆之差
  - 494：目标和，0-1背包方案数（转化：加减号分配）
    - 核心思路：P+N=sum, P-N=target → P=(sum+target)/2，转化为装满容量P的方案数
    - 坑点：(sum+target) 必须为偶数；|target| > sum 时直接返回 0；dp[0]=1 初始化
  - 474：一和零，0-1背包（二维费用）
    - 核心思路：每个字符串有 0 和 1 两个"费用"，二维 dp[j][k] 表示最多 j 个 0 和 k 个 1 的最大子集长度
    - 坑点：两个容量维度都必须倒序遍历；先统计每个字符串的 0/1 个数再做背包
  - P1048：采药，洛谷0-1背包模板题
    - 核心思路：经典0-1背包，每株草药只能采一次，时间即容量、价值即价值
  - 139：单词拆分，完全背包（字符串匹配变体）
    - 核心思路：dp[i] 表示 s[0..i-1] 能否被拆分，遍历字典单词匹配后缀
    - 坑点：找到一个匹配即可 break；注意 i >= len 的边界判断
  - 279：完全平方数，完全背包（最值型）
    - 核心思路：物品是 1,4,9,... 的完全平方数，求凑出 n 的最少个数
    - 坑点：因为不是求排列，两个循环顺序可颠倒；初始化 INT_MAX 需防溢出
  - 377：组合总和 Ⅳ，完全背包（排列数）
    - 核心思路：求凑出 target 的排列个数，外层遍历背包容量、内层遍历物品
    - 坑点：与组合数（518）的循环顺序相反——求排列先循环背包再循环物品
  - P1616：疯狂的采药，洛谷完全背包模板题
    - 核心思路：每株草药可重复采，完全背包正向遍历
    - 坑点：与 P1048 唯一区别是内层正序遍历（完全背包）vs 倒序遍历（0-1背包）
  - 70++：爬楼梯进阶版，完全背包（排列计数）
    - 核心思路：每次可爬 1~m 阶，dp[i] = sum(dp[i-j])，j=1..m
    - 坑点：与 377 同属排列型完全背包，外层遍历背包（台阶）、内层遍历物品（步长）
  - 322：零钱兑换，新增方法四（完全背包视角）—— 外层遍历硬币、内层正序遍历金额
  - 518：零钱兑换 II，数据类型改为 unsigned long long

## 5.5
- 完全背包专题：完成 1 道 LeetCode，对比同一题的两种实现——二维DP 与 一维滚动数组
  - 题型模板（可迁移）：完全背包（物品无限选取）
    - 适用信号：每种物品可无限次使用，求凑出目标的方案数/最值
    - 与0-1背包的关键区别：内层**正序**遍历容量（0-1背包必须倒序）
    - 状态转移：`dp[i][j] = dp[i-1][j] + dp[i][j - coin]`（不选 + 选了还能再选）
    - 坑点：方案数问题中间值可能远超最终答案，`int`/`long long` 均溢出；`unsigned int` 无符号溢出回绕是定义行为，恰好不影响32位以内的最终结果
  - 518：零钱兑换 II，完全背包计数
    - 核心思路：`dp[i][j]` 表示用前 i 种硬币凑出金额 j 的方案数
    - 转移方程：`dp[i][j] = dp[i-1][j] + dp[i][j - coins[i-1]]`（不选第 i 种 + 选第 i 种）
    - 一维优化：`dp[j] += dp[j - coin]`，外层遍历硬币、内层正序遍历金额
    - 坑点：循环边界 `i <= n` 不是 `i < n`，漏掉最后一行导致返回 0；数据类型必须用 `unsigned int`，`int` 溢出变负、`long long` 中间值超 2^63 触发 UBSan

## 5.4
- 0-1背包专题：完成 1 道 LeetCode，同一题两种实现对比——一维滚动数组 vs 二维DP
  - 416：分割等和子集，0-1背包判定问题
    - 问题转化：能否将数组分成两个和相等的子集 → 能否从数组中选出若干数使其和恰好为 `sum/2`
    - 方法一（一维DP优化）：`dp[j]` 表示能否凑出和为 j 的子集，外层遍历物品、内层倒序遍历容量保证每个物品只用一次，`dp[j] = dp[j] || dp[j - nums[i]]`，提前判断 `dp[target]` 剪枝
    - 方法二（二维DP）：`dp[i][j]` 表示考虑前 i 个物品能否凑出和 j，虚拟行避越界，正序遍历
    - 坑点：总和为奇数时直接返回 false；一维DP内层必须倒序，否则同一物品被重复选取退化为完全背包

## 5.3
- 哈希表 + 排序 + 投票算法专题：完成 1 道 LeetCode，同一题三种解法对比
  - 169：多数元素，摩尔投票法/哈希表计数/map+vector自定义排序
    - 方法一（摩尔投票法）：维护候选 `ans` 和计数 `cnt`，不同则抵消，相同则累加，最终剩下的即为多数元素，O(n) 时间 O(1) 空间
    - 方法二（哈希表计数）：遍历统计频次，超过 n/2 即返回，O(n) 时间 O(n) 空间
    - 方法三（map+vector排序）：map 统计频次后转 vector，自定义 lambda 按 second 降序排序取首元素，O(n log n)
    - 坑点：摩尔投票法前提是多数元素一定存在（题目保证），否则需二次验证

## 5.2
- 滑动窗口 + 前缀和二分专题：完成 1 道 LeetCode，对比同一题的两种解法——滑动窗口 O(n) 与前缀和+二分 O(n log n)
  - 209：长度最小的子数组，滑动窗口/前缀和+二分
    - 方法一（滑动窗口）：右扩累加，`sum >= target` 时左缩更新最小长度，O(n)
    - 方法二（前缀和+二分）：因元素正数，前缀和单调递增，对每个左端点 `i` 二分找第一个 `preSum[r+1] >= preSum[i] + target`，O(n log n)
    - 坑点：前缀和方法依赖元素恒正才单调，若含负数则只能用滑动窗口；`lower_bound` 搜索范围从 `preSum.begin()+i+1` 开始避免重复选取

## 5.1
- 前缀和 + 哈希表专题：完成 5 道 LeetCode，系统梳理"前缀和+哈希表"的三种变体——计数型、存在性型、最值型
  - 题型模板（可迁移）：前缀和 + 哈希表求子数组问题
    - 适用信号：题目要求统计/判断/最值某种"子数组和"的性质（等于k、被k整除、为0等）
    - 通用步骤：遍历数组维护前缀和 → 对前缀和做变换（取模/直接用/映射） → 哈希表查询匹配值 → 更新答案
    - 两种存储策略：计数类存频次 `{值: 次数}`，最值/存在性类存首次索引 `{值: 最早下标}`
    - 兜底初始化：`preMap[0] = -1`（索引型）或 `preFreq[0] = 1`（频次型），处理子数组从头开始的情况
    - 坑点：C++ 负数取模需 `(preSum % k + k) % k` 修正；只记录首次出现索引才能让子数组尽可能长
  - 560：和为 K 的子数组，前缀和+哈希表计数
    - 核心思路：`preSum[j] - preSum[i] = k`，查找 `preSum - k` 出现的次数
    - 坑点：每次都要更新频次 `preFreq[preSum]++`，因为相同前缀和可贡献多个子数组
  - 974：和可被 K 整除的子数组，前缀和+哈希表+同余计数
    - 核心思路：`(preSum[j] - preSum[i]) % k == 0` 等价于两者余数相同，用余数作为哈希表 key
    - 坑点：C++ 负数取模结果为负，必须 `(preSum % k + k) % k` 保证非负
  - 523：连续的子数组和，前缀和+哈希表+同余存在性
    - 核心思路：与 974 同余思想，但只需判断存在性且要求子数组长度 >= 2
    - 坑点：只在余数首次出现时记录索引，保留最早位置使子数组尽可能长
  - 525：连续数组，前缀和+哈希表求和为0的最长子数组
    - 核心思路：将 0 映射为 -1、1 保持不变，问题转化为求和为 0 的最长子数组
    - 坑点：`preMap[0] = -1` 兜底；只在首次出现时记录索引
  - 1124：表现良好的最长时间段，前缀和+哈希表求最长正和区间
    - 核心思路：`>8h` 映射为 +1、`≤8h` 映射为 -1，求 `preSum[i] - preSum[j] > 0` 的最长区间
    - 坑点：只需找 `preSum - 1`（最容易满足 > 0 的条件），不是找所有更小的值
