## 5.19
- CSP 2024年3月真题训练：新增 2 道 CSP 题目（T4 + T5），重点学习 set mutable 技巧和 DFS 序 + 树状数组维护子树操作
  - CSP202403D：水滴爆炸链式反应，set + mutable + 优先队列
    - 核心思路：用 `set<drop>` 按位置排序，`mutable int w` 允许通过 const 迭代器原地修改重量；priority_queue（小根堆）维护待爆炸位置；`prev(it)` / `next(it)` 找左右邻居触发连锁反应
    - mutable 技巧：键（位置）不可变决定排序，附加值（重量）用 mutable 标记实现原地 `it->w++`，比"删除再插入"更高效且迭代器不失效
    - 坑点：`find({key, 0})` 中附加值填什么都行，只比较键；爆炸后需检查迭代器是否已失效（`cur_it == s.end()`）
  - CSP202403E：文件系统合并与查询，DFS 序 + 树状数组 + 手写链表
    - 核心思路：将树形结构通过 DFS 序"拍扁"为一维数组，子树操作转化为区间操作；用差分数组 + 树状数组维护每个节点的深度，支持 O(logN) 的子树深度加减和单点查询
    - 关键操作：合并子文件夹时，销毁直接子节点并将其孙节点提拔为儿子（左儿子右兄弟链表的 O(1) 指针操作）；数据量通过 `d[x] += d[child]` 累加后回收
    - 手写链表优化：用 `head[u]` / `tail[u]` / `nxt[v]` 模拟邻接表，避免 `vector<vector<int>>` 的内存拷贝开销
    - 坑点：DFS 序的 `in_time` 和 `out_time` 划定子树区间边界，合并操作中遍历子链表时需先保存 `nxt[curr]` 再修改指针；`ios::sync_with_stdio(false)` + `cin.tie(nullptr)` 是 5e5 数据量的标配
  - P1908：逆序对，树状数组 + 离散化
    - 核心思路：从右往左遍历，对每个元素查询"右边严格小于它的个数"并累加；值域到 10^9 需先离散化
    - 离散化三部曲：排序 → `unique` 去重 → `lower_bound` 查 rank（+1 对齐树状数组下标从 1 开始）
    - 坑点：重复数字只算严格小于（`query(rank-1)` 而非 `query(rank)`）；答案用 `long long`（n=5e5 时逆序对可达 ~1.25e11）
  - 新增专题笔记：[区间数据结构](../notes/区间数据结构.md)——前缀和、差分数组、树状数组、线段树、ST 表的完整速查手册，包含五种模式（区间和、单点修改区间和、区间修改区间和、区间最值、子树操作）的模板和复杂度对比

## 5.16
- CSP 2024年3月真题训练：完成 2 道 CSP 题目（T2 + T3），重点攻克浮点数比较和高斯消元
  - **血泪教训：浮点数判零必须用 `abs(x) < EPS`，绝对不能用 `== 0`！**
    - 浮点运算（加减乘除）会产生微小误差，`== 0` 几乎永远为 false，导致逻辑完全错乱
    - 正确写法：`const double EPS = 1e-7; if(abs(x) <= EPS) ...`（C++ 用 `abs()`，C 用 `fabs()`）
    - 本题 CSP202403C 高斯消元中，判断主元是否为零、判断列是否全零，全部依赖 `abs(mp[i][y]) > EPS`，一个 `== 0` 就全错
    - **记住：只要涉及浮点数，所有等于零的判断、等于某个值的判断，全部转换为差值的绝对值 < EPS**
  - CSP202403B：相似度计算，集合交并集
    - 核心思路：运用 `set` 自动去重和排序，配合双指针遍历求交集大小；通过容斥原理 `|A| + |B| - |A ∩ B|` 求并集大小。
    - 坑点：使用 `tolower` 统一转小写；直接算并集大小，避免再产生一个新的并集集合。
  - CSP202403C：化学方程式配平，高斯消元求矩阵秩
    - 核心思路：将化学方程式配平转化为齐次线性方程组 Ax=0，判断系数矩阵的秩是否小于未知数个数（物质数 m）；若 rank < m 则存在非零解（可配平），否则不可配平。
    - 方法一（浮点高斯消元）：用 double 存矩阵，高斯消元逐列消去求秩；**判零必须用 `abs(x) <= 1e-7`**，不能用 `== 0`
    - 方法二（模意义高斯消元）：用 `long long` 存矩阵，模 998244353 运算，用费马小定理求乘法逆元替代除法，彻底规避精度问题
    - 坑点：化学式解析需按"连续字母+连续数字"成对提取；元素数 < 物质数时直接输出 Y（方程数少于未知数必有非零解）

## 5.12
- CSP 2025年9月真题训练：完成 2 道 CSP 题目（T2 + T3），重点学习 Huffman 编码解码和阈值区间约束优化
  - 题型模板（可迁移）：Huffman 树先序建树 + 比特流解码
    - 适用信号：给定 Huffman 树的先序描述（0=内部节点，1=叶子+字符），需要将十六进制编码比特流还原为原串
    - 通用步骤：先序遍历建树生成 path→char 映射 → hex 展开为比特流 → 去掉末尾补 0 → 逐 bit 沿树匹配叶子输出字符
    - 复杂度：建树 O(|T|)，解码 O(比特数)
    - 坑点："HH" 是转义字符串（去掉第一个 H），单个 "H" 开头才是 Huffman 编码；末字节补 0 数 p 存在最后一个 hex 字符中
  - 题型模板（可迁移）：二值化阈值匹配固定模式——像素约束转 k 的区间
    - 适用信号：灰度图像按阈值 k 二值化后匹配固定黑白模式
    - 通用步骤：遍历窗口 → 白点取 minWhite、黑点取 maxBlack → 合法 k 在 [maxBlack+1, minWhite] → 标记区间
    - 复杂度：O(n²)，每窗常数点检查
    - 坑点：>=k 为白、<k 为黑，区间端点截断到 [0, L-1]；暴力枚举 k 的 O(L×N²) 只能过 80%
  - CSP202509B：图像二值化水印检测，枚举优化/区间约束
    - 核心思路：把每个像素对阈值 k 的约束转成区间，窗口内 45 个像素的约束取交集
    - 方法一（暴力）：对每个 k 遍历全图检查模式，O(L×N²)，80/100
    - 方法二（优化）：遍历每个窗口，统计白点 minWhite 和黑点 maxBlack，标记合法区间，O(45×N²)，满分
    - 坑点：首行首列全白是额外约束，必须纳入 minWhite 统计
  - CSP202509C：HPACK Huffman 编码解码，Huffman 树 + 表驱动 + 动态表
    - 核心思路：先序编码建 Huffman 树 → 十六进制转比特流沿树解码 → 指令驱动维护静态/动态表
    - 动态表用 deque 前插，编号 S+1，容量超限丢弃末尾；引用编号 i > S 时用 `i-(S+1)` 定位
    - 坑点：字符串三种格式（普通/Huffman/转义）需统一处理；末字节补 0 和补位计数字节 p 的处理
- 详细笔记见 [哈希表与字符串](../notes/哈希表与字符串.md)（新增：Huffman 编码解码模板）、[矩阵技巧](../notes/矩阵技巧.md)（新增：二值化阈值模式匹配模板）

## 5.8
- 蓝桥杯背包变体 + Nim博弈专题：完成 3 道题目（1 LeetCode + 2 蓝桥杯），重点攻克比赛中背包问题的复杂变体——带时间间隔约束的背包、带承重堆叠约束的背包
  - 题型模板（可迁移）：带冷却时间的 0/1 背包（时间轴背包）
    - 适用信号：物品分布在时间轴上，选取有"间隔 >= K"约束，同时有总预算/容量上限
    - 通用步骤：按时间离散化物品 → dp[time][budget] 维护前 time 个时间单位、预算不超 budget 的最值 → 转移为不选当前时间 or 选当前时间的某物品（从 dp[time-K] 转移）
    - 复杂度：O(T * M + N)，T 为时间范围，M 为预算上限
    - 坑点：间隔约束用 dp[time-K] 而非 dp[time-1]；同一时间点可能有多个物品需遍历
  - 题型模板（可迁移）：承重/堆叠约束的 0/1 背包（排序+背包）
    - 适用信号：物品有"承重"和"价值"双重属性，堆叠时上方总重不能超过下方物品的价值
    - 通用步骤：按 w+v 排序（保证加入当前物品时，上方总重不超过其价值）→ dp[totalWeight] 维护总重量为 totalWeight 的最大价值 → 0/1 背包倒序遍历，上界用 w+v
    - 复杂度：O(n * Wmax)，Wmax 为可达最大总重量
    - 坑点：必须按 w+v 排序而非按 w 或 v 单独排序；转移上界是当前物品的 w+v 而非全局常量；答案取所有 dp[j] 的最大值
  - 292：Nim 游戏，博弈论
    - 核心思路：每次可拿 1~3 块，拿走最后一块者胜 → 只要 n 不是 4 的倍数就能赢（先手拿 n%4 块，之后无论对手拿 k，自己拿 4-k 保持 4 的倍数）
    - 坑点：n%4==0 时先手必输，不是 n%4!=0 时必输
  - 2195：费用报销，蓝桥杯，带冷却时间的 0/1 背包
    - 核心思路：将月/日映射到 1~365 绝对天数，dp[day][budget] 维护前 day 天、预算不超 budget 的最大报销额，间隔 K 天约束从 dp[max(0, day-K)] 转移
    - 坑点：同一天可能有多张票据需遍历；prev_day = max(0, i-K) 处理前 K 天无可选历史；12 月底不影响 1 月初（非闰年，不跨年）
  - 2201：搬砖，蓝桥杯，承重堆叠约束的 0/1 背包
    - 核心思路：按 w+v 排序后，每块砖的承重上限为其自身 v，总重量上限为 w+v；dp[j] 维护总重为 j 的最大价值，0/1 背包倒序遍历
    - 坑点：dp 数组上界由数据范围决定（w<=20, v<=20000 → Wmax<=20020）；答案取全局 dp 最大值而非某个固定重量点

  - 题型模板（可迁移）：多重背包——二进制拆分转 0/1 背包
    - 适用信号：物品有数量上限 k[i]，不能无限选也不能只选一件
    - 通用步骤：对每类物品按 1,2,4,...2^n 拆分，剩余尾数单独成件 → 拆分后每件视为独立的 0/1 物品 → 跑标准 0/1 背包（一维 dp 倒序遍历）
    - 正确性：二进制拆分保证每个可选数量 [0, k[i]] 都能由若干拆分件组合得到
    - 复杂度：拆分件数 O(sum log k[i])，总体 O(C * sum log k[i])，空间 O(C)
    - 坑点：容量必须逆序更新；拆分时要正确扣减剩余数量，尾数不能漏
  - 2073：买票需要的时间，队列模拟
    - 核心思路：用队列存下标，每次队首买票（tickets[cur]--），time++，买完且是目标 k 则返回
    - 方法二（数学）：k 前面的人最多买 tickets[k] 张，后面的人最多买 tickets[k]-1 张，累加 min 即可
    - 坑点：队列模拟法中，tickets[cur]==0 时不再入队；目标 k 买完才返回，不是 tickets[k]==0
  - 933：最近的请求次数，队列+滑动窗口
    - 核心思路：queue 维护时间窗口，每次 ping(t) 先入队，再弹出所有 < t-3000 的旧请求，返回队列大小
    - 坑点：是 while 循环弹出所有过期请求，不是 if 只弹一个
  - 1174：小明的背包，蓝桥杯 0/1 背包模板
    - 核心思路：标准 0/1 背包，一维 dp 倒序遍历容量
    - 坑点：无特殊坑点，纯模板题
  - 56++：携带矿石资源，多重背包（二进制拆分）
    - 核心思路：每种矿石有数量上限 k[i]，用二进制拆分将每类矿石拆成 O(log k[i]) 件独立物品，再跑 0/1 背包
    - 方法二（朴素多重背包）：在 0/1 背包基础上加一层遍历 n[i] 次的循环，O(C * N * k[i]) 可能超时
    - 坑点：二进制拆分后尾数不能遗漏；C<=2000、N<=100，拆分后规模可控

  - 139：单词拆分，完全背包（字符串匹配变体）
    - 核心思路：dp[i] 表示 s[0..i-1] 能否被拆分，遍历字典单词匹配后缀
    - 坑点：找到一个匹配即可 break；注意 i >= len 的边界判断
  - 279：完全平方数，完全背包（最值型）

    - 坑点：因为不是求排列，两个循环顺序可颠倒；初始化 INT_MAX 需防溢出
  - 377：组合总和 Ⅳ，完全背包（排列数）

## 5.5
- 完全背包专题：完成 1 道 LeetCode，对比同一题的两种实现——二维DP 与 一维滚动数组
  - 题型模板（可迁移）：完全背包（物品无限选取）
    - 适用信号：每种物品可无限次使用，求凑出目标的方案数/最值
    - 与0-1背包的关键区别：内层**正序**遍历容量（0-1背包必须倒序）
    - 状态转移：`dp[i][j] = dp[i-1][j] + dp[i][j - coin]`（不选 + 选了还能再选）
    - 坑点：方案数问题中间值可能远超最终答案，`int`/`long long` 均溢出；`unsigned int` 无符号溢出回绕是定义行为，恰好不影响32位以内的最终结果
  - 518：零钱兑换 II，完全背包计数
    - 核心思路：`dp[i][j]` 表示用前 i 种硬币凑出金额 j 的方案数
    - 转移方程：`dp[i][j] = dp[i-1][j] + dp[i][j - coins[i-1]]`（不选第 i 种 + 选第 i 种）
    - 一维优化：`dp[j] += dp[j - coin]`，外层遍历硬币、内层正序遍历金额
    - 坑点：循环边界 `i <= n` 不是 `i < n`，漏掉最后一行导致返回 0；数据类型必须用 `unsigned int`，`int` 溢出变负、`long long` 中间值超 2^63 触发 UBSan

  - 题型模板（可迁移）：前缀和 + 哈希表求子数组问题
    - 适用信号：题目要求统计/判断/最值某种"子数组和"的性质（等于k、被k整除、为0等）
    - 通用步骤：遍历数组维护前缀和 → 对前缀和做变换（取模/直接用/映射） → 哈希表查询匹配值 → 更新答案
    - 两种存储策略：计数类存频次 `{值: 次数}`，最值/存在性类存首次索引 `{值: 最早下标}`
    - 兜底初始化：`preMap[0] = -1`（索引型）或 `preFreq[0] = 1`（频次型），处理子数组从头开始的情况
    - 坑点：C++ 负数取模需 `(preSum % k + k) % k` 修正；只记录首次出现索引才能让子数组尽可能长
  - 560：和为 K 的子数组，前缀和+哈希表计数
    - 核心思路：`preSum[j] - preSum[i] = k`，查找 `preSum - k` 出现的次数
    - 坑点：每次都要更新频次 `preFreq[preSum]++`，因为相同前缀和可贡献多个子数组
  - 974：和可被 K 整除的子数组，前缀和+哈希表+同余计数
    - 核心思路：`(preSum[j] - preSum[i]) % k == 0` 等价于两者余数相同，用余数作为哈希表 key
    - 坑点：C++ 负数取模结果为负，必须 `(preSum % k + k) % k` 保证非负
  - 523：连续的子数组和，前缀和+哈希表+同余存在性
    - 核心思路：与 974 同余思想，但只需判断存在性且要求子数组长度 >= 2
    - 坑点：只在余数首次出现时记录索引，保留最早位置使子数组尽可能长
  - 525：连续数组，前缀和+哈希表求和为0的最长子数组
    - 核心思路：将 0 映射为 -1、1 保持不变，问题转化为求和为 0 的最长子数组
    - 坑点：`preMap[0] = -1` 兜底；只在首次出现时记录索引
  - 1124：表现良好的最长时间段，前缀和+哈希表求最长正和区间
    - 核心思路：`>8h` 映射为 +1、`≤8h` 映射为 -1，求 `preSum[i] - preSum[j] > 0` 的最长区间
    - 坑点：只需找 `preSum - 1`（最容易满足 > 0 的条件），不是找所有更小的值
